# 城市街景背景

背景使用本地生成的 SVG。包含远近两层建筑、店铺雨棚、人行道、双向道路、斑马线、路标、信号灯、路灯、车辆、行人和行道树。相同地点及形态的布局使用固定种子，刷新天气或切换语言不会重新随机排列。GeoTIFF.js 按需读取全球 LCZ 栅格中的小块区域。

## 建筑分级

| 已观测的局地建筑形态 | 背景 |
| --- | --- |
| LCZ 1、4：紧凑/开敞高层 | 高楼 |
| LCZ 2、5：紧凑/开敞中层 | 中层建筑 |
| LCZ 3、6：紧凑/开敞低层 | 低层建筑与店铺 |
| LCZ 7、8、9：轻型低层、大型低层、稀疏建筑 | 低层建筑与店铺 |
| 未知、没有来源、工业或自然类型 | 通用街景（中层绘制模板） |

中国和其他国家采用同一套建筑形态依据。行政区级别、首都/省会身份、名称后缀和人口总量不参与建筑高度判断。已经移除省会坐标名单、县城强制低层及国外人口阈值。

LCZ（Local Climate Zones，局地气候区）是描述局部城市形态的分类体系，考虑建筑与树木高度、建筑密度及地表覆盖，适用尺度为数百米至数公里。它用于城市气候研究，不是建筑法规中的单体建筑高度定义，也不是整座城市的行政排名。同一城市的商务区、老城和郊区可能属于不同类别。

LCZ 1–3 和 7 采用紧凑布局，减少楼间距与树木；4–6 和 8 采用开敞布局；9 增大楼间距。LCZ 8 使用更宽的低层平顶建筑。工业和自然类型暂用通用模板，不把它们解释成真实中层城市。这里是对 LCZ 的风格化表达，不还原真实楼栋外观或完整工业/自然景观。

## 数据与降级

- **已接入 Global LCZ Map v3**：数据来源为 Demuzere 等作者与 WUDAPT 贡献者，空间分辨率约 100 米，名义基准年为 **2018**。v3 于 2023 年发布，是分类地图，不是当前年份逐栋建筑实测。采用官方 COG：`https://lcz-generator.rub.de/cogs/lcz_filter_v3_cog.tif`，来源记录：`https://zenodo.org/records/8419340`。
- 天气先显示，LCZ 模块随后加载。读取地理编码查询坐标周围 **500 米半径**内的原始分类像元；排除无数据像元及圆形范围以外的角点。居住/工业像元（1–10）合计超过有效样本的一半时，在这些类别中取最多的类别；否则在自然类别（11–17）中取最多的类别。并列优先中心像元类别，再按类别编号确定，避免随机跳变。这个聚合规则是本项目选择，不是 LCZ 标准的附加规定。
- `CityPlace.urbanForm` 保存 `lczClass`、可追溯的 `source`、`referenceYear`、`sampleRadiusM`、`sampleCount` 与 `classShare`。`classShare` 表示该类别占有效样本的比例，不是模型准确率或建筑高度占比。
- `/api/lcz-raster` 是同源 EdgeOne 边缘函数，代理固定版本数据的单个、有界 HTTP Range，每次最多 2 MiB。拒绝整文件响应、错误 Content-Range 和长度，GeoTIFF.js 也禁止整文件下载；栅格块按需读取，不下载完整的约 1.7 GB 地图。代理覆盖浏览器跨域限制，不接受任意上游 URL。
- 当前页面缓存最近 128 个查询点，成功数据有效 24 小时，无数据有效 1 分钟。切换地点取消旧读取；迟到结果不能覆盖新地点。30 秒超时、服务故障、范围外或无数据时保留通用街景，不影响天气。数据源的覆盖范围大致为 170°W–180°E、60°S–80°N。
- 地理编码字段仍用于地点检索、同名消歧和候选合并，不将其转换成 LCZ，也不发起仅用于推断高楼的额外 Open-Meteo 查询。
- 刷新或切换语言保留已选择地点的建筑形态，反向编码返回附近区县时不覆盖原地点。

## 天气联动与可访问性

天空优先读取天气接口的 `clouds.all` 云量百分比，缺少云量时按天气代码回退。晴、少云、疏云、多云、阴天使用 0、2、4、6、8 组由多个椭圆云团组成的云；雨、雪、雷暴分别使用不同厚度与色调，雾天采用漫射雾层。云团缓慢向同一方向漂移，天气形态和数量不变时保留云层布局与动画进度。

白天晴朗天空采用亮蓝至浅蓝渐变，阴天采用较亮的灰蓝漫射光；全屏黑色遮罩已移除，明亮背景使用深蓝文字。夜间有独立配色，云、雨、雪的白天颜色不能覆盖夜景。原先巨大的琥珀色圆斑改成较小的日/月光点；阴天不显示太阳，夜间阴天也不显示月亮。更新时间使用局部半透明底色，避免街景挡住小字。

天空背景中的月亮使用实时月相；页面中间的天气图标保持原有固定样式。SunCalc 2.1.1 在浏览器内计算当前绝对时刻的受光比例、盈亏阶段与亮边位置角，不请求额外接口，也不把城市时区偏移或缓存天气时间戳当作计算时间。SVG 用圆弧与椭圆明暗边界绘制新月、月牙、弦月、凸月和满月；暗面仅以很低的不透明度作风格化轮廓。城市经纬度用于计算视差角并调整月面的倾斜方向；没有有效坐标时使用北向朝上的常规月相示意。刷新天气、切换地点及语言时更新，另每 12 分钟以及页面重新可见时独立更新。日间太阳和阴雨天的遮蔽规则沿用原有设置；月亮的屏幕位置仍为装饰布局，不表示实际高度、方位或升落。

计算说明：[SunCalc 官方文档](https://github.com/mourner/suncalc#moon-illumination)。单元测试使用 [USNO 2026 年 10 月主要月相时刻](https://aa.usno.navy.mil/api/moon/phases/date?date=2026-10-01&nump=5) 作独立参考，另外检查 SVG 亮面面积、时区一致性，以及背景月相更新时中间天气图标保持原样。

雨雪只在微型城市 SVG 内显示，使用街景自身的坐标和裁剪范围。雨滴是细小的斜线，雪花是小颗粒，分别在远楼后、中间楼层之间和近景街道上运动；页面不再有整屏雨雪粒子层。裁剪范围随高、中、低层街景调整，顶部淡入、到街道淡出，行人、树木和车辆绘制在近景降水前面。

轻、中、强雨分别启用 28、52、84 个雨滴；对应雪档启用 34、60、92 个雪粒。强度变化通过 CSS 切换粒子档位，不重新排列城市。雨天显示路面反光、水洼、落地涟漪和行人雨伞；雪天显示屋顶、树冠与路沿积雪，积雪表现随视觉强度变化。积雪是装饰性表达，不代表观测雪深。天气图标内的小雨雪动效保留。

夜间亮窗灯、路灯和车灯；雾天降低街景可见度。装饰位于 `aria-hidden` 的天气背景中，不接收点击。手机减少场景高度；`prefers-reduced-motion` 下隐藏飘落粒子与涟漪，保留静态雨伞、反光和积雪，车辆、行人和树木保持静止。

## 维护

- `src/city-profile.ts`：地点字段转换、候选合并与 LCZ 高度类别映射。
- `src/lcz-sampling.ts`：坐标到栅格窗口、500 米圆形邻域聚合。
- `src/lcz-data.ts`、`src/lcz-client.ts`：按需数据读取、缓存。
- `edge-functions/api/lcz-raster.js`：有界栅格 Range 代理。
- `tools/preview.mjs`：本地静态页面与 LCZ 代理预览，运行 `npm run preview`。
- `src/city-scene.ts`：确定性 SVG 街景生成。
- `src/city-weather.ts`：城市范围内的分层降水、水洼与涟漪。
- `src/sky-scene.ts`、`src/sky-scene.css`：云量与云团、白天/夜间天空配色及文字对比。
- `src/moon-phase.ts`：实时月相、受光轮廓与所选地点的月面倾斜方向；SunCalc 许可证随构建输出到 `suncalc-license.txt`。
- `src/city-scene.css`：配色、天气联动、动画及响应式样式。
- 测试覆盖行政与人口不参与推断、LCZ 映射、邻域聚合、缓存、代理边界、地点切换与失败回退。单元测试中的 LCZ 是人工测试数据；真实服务另作在线验证。
